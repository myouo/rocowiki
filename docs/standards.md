<a id="structure"></a>
## 目录与数据权威

apps/web 负责界面，apps/api 负责身份与写入；packages 承担协议、认证、内容校验、Git 和发布职责。新增公共能力放在相应边界，不把数据库、凭据或服务器业务复制到前端。前端资料通过 wiki/content/bundled.js 接入；正式编辑目标依根 catalog，不猜测类似页面名称。Git 的受审内容与 D1 的身份/工作流各有权威范围，浏览器演示不能升级为服务端记录。

<a id="code"></a>
## 代码与生命周期

新业务模块使用 TypeScript 和明确的数据类型；遗留 JS 分模块补 JSDoc/checkJs 或迁移。禁止用宽泛 any、双重断言、ts-nocheck 或关闭检查隐藏错误。外部数据先校验，再在业务中使用。模型不依赖 React 或 Docusaurus，模块职责单一，保持现有依赖边界与文件规模门禁。

组件的请求、定时器、observer、事件和 portal 随所属 document/生命周期清理；不读取已经卸载或为空的 DOM，不在旧请求完成时覆盖新页面。响应式检查至少涉及窄屏、桌面、长内容、键盘和空/错误状态。复用柔和背景、圆角和统一内容宽度，不另造一套详情页样式。

<a id="security"></a>
## 安全与故障

遵守 SECURITY.md。所有公开输入经过 schema 与内容校验；正文、元数据和请求大小使用字节边界。重试保留幂等键/资源 ID；区分确认成功、确认删除、临时失败和权限错误。事务保护状态、事件与进度，租约保护并发；不要静默丢弃失败记录。新增错误码提供安全且可理解的文案，不记录令牌、Cookie、私钥或用户正文。

<a id="changes"></a>
## 接口、依赖与迁移

接口变更同时更新服务端响应、前端契约和必要联测。数据库迁移追加编号文件，不编辑已经应用的迁移；说明对旧会话/草稿/历史事件的影响。必要时先迁移，再部署兼容代码。依赖更新锁文件，说明用途与许可，避免多套重复库；不要把为测试准备的绕过机制放进生产路径。

<a id="tests"></a>
## 验证要求

按风险选择验证：认证/授权、不可变快照、审核、发布、失败恢复需要真实契约、SQL 或上游边界回归；界面问题需要实际组件或浏览器证据。可逆的小文字/样式改动不要求制造形式化测试。类型门禁只证明纳入检查的文件，mock 不证明真实平台已接入。具体命令见 CONTRIBUTING.md，验证报告写明未覆盖范围。

<a id="docs"></a>
## 双语与生成文件

规范文档以 docs/policies.json 登记，中英文同步修改版本、章节和要求；自动检查不替代语义复核。重要决策用 ADR 说明背景、方案、后果及双语摘要。示例只使用 .test/example 域名、合成账号和空 Secret。所有生成输出从受控输入重建；保留源文件、锁文件、来源、哈希及许可，历史设计归档不作为当前运行输入。

运行 npm run check:repository 检查政策版本/章节、语言互链、相对文件链接、项目/锁文件许可、台账版本/原文哈希、Git 候选文件和分支禁用词。它已纳入 check 和生产制品构建；只识别有限凭据模式，不读取已忽略的本机 Secret，也不扫描完整 Git 历史或验证翻译语义/素材授权。直接依赖变化后运行 npm run licenses:refresh 并审阅输出；不要仅更新哈希来绕过实际的内容或许可复核。

<a id="release"></a>
## 发布纪律

保持独立审核、main 保护和发布 App 的文件白名单，不直接覆盖已审正文或自动三方合并。发布前复核生产配置、迁移、待处理巡检错误、内容权利和源码可获取方式。分发 GPL 代码时保留 LICENSE、原版权/第三方声明并提供对应源码；具体权利以 LICENSE 和各文件原声明为准。外部后台保护、真实报告渠道、备份与 PoC 必须真实配置，文档存在不代表已生效。
