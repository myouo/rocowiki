# 天梯历史资料调查与入口分配

调查日期：2026-10-24，范围为洛克王国页游。实现基线：`04e141bab53758afe983dd766f8916157b9fde29`。

本轮从原始公告、官方图鉴获取描述、公开天梯配置和仓库旧快照建立第一批可查询档案。它覆盖了可追溯的记录，不把尚缺的届次、日期和领取方式补成确定事实。

## 值得维护的历史信息

| 信息 | 玩家会查的问题 | 归属与优先级 |
| --- | --- | --- |
| 历届赛季与结算 | 某届何时结算？开赛、停办、恢复和领奖截止分别是哪一天？ | 历届赛季；优先保存分别有依据的日期，不从季度或前一届推算 |
| 奖励宠物、服装、边框与称号 | 哪一届能获得，门槛是什么，后来是否返场？ | 奖励索引与对应赛季；宠物来源先接入，其他奖励逐字段补证据 |
| 历史禁赛 | 某期哪些宠物被禁？天梯与系别是否相同？ | 历史禁赛；模式、记录日期和证据类型一起保存 |
| 魔力费用 | 何时新增或调整费用？原值是否明确？ | 历史变动与配置比较；新增记录不自动解释为从 1 变到该数值 |
| 互斥与参赛限制 | 哪些组合曾被限制，何时新增或取消？ | 规则沿革，后续按有日期的原公告补录；不能从当前互斥倒推过去 |
| 兑换商城 | 什么时候上新、下架或返场？ | 费用与兑换；与赛季结算奖励分开 |
| 段位与胜点、巅峰门槛 | 段位分界、连胜、重置和解锁条件曾如何改变？ | 规则沿革；未核实的历史公式保留调查项 |
| 日常任务与成就 | 任务、梦想积分、徽章及赛季宝箱怎样变化？ | 奖励或规则的独立记录；需要明确日期，不能套用今天的数值 |
| 结算预告、图集与活动 | 赛季前的预告活动、历程图集奖励在哪一段开放？ | 赛季关联事件；活动日期不等于赛季全程 |
| 特殊时间调整 | 节假日提前禁赛、延期结算、停办与恢复有哪些公告？ | 日程沿革；只有正文可读的明确证据才写入正式字段 |

赛季胜率、环境统计和玩家榜单也可研究，但需要对应时期的完整、可公开核验的数据；本轮没有以零散对局或当下配队推导历史环境排名。

## 本轮找到的材料

从[官方新闻目录](https://roco.qq.com/webplat/info/news_version3/397/838/839/840/m681/list_1.shtml)跟随真实分页和旧页导航，读到 **2025-10-24 至 2026-10-23 共 53 份周更公告**。本轮直接保存其中的事实字段和出处，没有将公告全文及图片纳入仓库。

官方图鉴的 `getForm` 有 **37 届、38 条明确带届次的天梯获取记载**，分布在第 1 至第 42 届之间；第 7、8、9、16、19 届尚未由本次这份配置得到明确对应。部分宠物的描述仅写“参与天梯赛获得”，这些记录没有被猜填到某一届。

第一批数据见[天梯历史数据](../../apps/web/content/ladder-history.json)，包含：

- 37 届及 38 条奖励宠物记载；原文明确段位时才填写领取条件。
- 53 条天梯公告禁赛记录、6 条选定的系别比赛日记录；天梯和巅峰只共享已说明的禁赛资料。
- 14 条原公告中的费用新增或兑换商城变动。
- 一条第 39 届结算预告关联事件；第 39–42 届公告明确共用的天梯、巅峰结算范围分别保留。
- 两份有独立来源指纹的配置观测，最早与最近的北京时间采集日分别为 2026-10-12、2026-10-22；不把它们解释成整段生效期。
- 第 39–42 届结算日期对应当期原始公告。开赛时间及独立领奖截止未有相同强度证据时保留空缺。

所有公告记录都有原始 URL、提取正文的指纹、采集时间与读取位置。配置另保留原包指纹；二者不混为同一种版本证据。

## 证据取舍

1. 第 40 届在二手汇总中出现“结束时间 2026-03-20”，而[3 月 13 日官方周更](https://roco.qq.com/webplat/info/news_version3/397/838/839/840/m682/202603/983232.shtml)明确记载当日结算。本轮只填可直接核对的结算日；不把它扩成开赛、结束和领奖截止，也不把不同字段强行合并。
2. 官方图鉴同一届可能关联不止一只宠物。本轮保留每条获取描述，没有假定它们采用同一领取形式、都是高级奖励或互相替代。
3. 2026-02-13、2026-02-20 的原公告明确写无禁赛，因此保存空名单。其他日期未收录时返回未知，不使用同一种空态。
4. 原始论坛中的部分旧公告仍有标题但正文空缺，二手存档中的提前禁赛和互斥调整只作为后续寻源线索，本轮没有据标题建立确定规则。
5. 图鉴只笼统写天梯获得的宠物不强行归届。现有 XML 的奖励文案与道具 ID 只作为该次配置的观测，不自动套到所有赛季或宣称实际发放内容。

## 入口分配与兼容

主入口是 `/battle/history/`，位于现有“对战与禁赛”页面操作区及页尾。保留 PVP 顶级导航，档案在现有天梯系统内展开。

| 阅读目的 | 入口 |
| --- | --- |
| 查某届与日期依据 | `?view=seasons&season=42` |
| 查某只奖励宠物 | `?view=rewards&q=姝绒`，并从宠物条目的来源区反向链接到对应届次 |
| 查当期公告禁赛 | `?view=bans&record=ladder-2026-02-13` |
| 查系别或巅峰共享名单 | 禁赛页内切换模式，保留模式语境 |
| 查配置观测 | 禁赛选择框中的“配置采集”，展开费用与奖励字段 |
| 查费用新增、商城上新/下架 | `?view=changes`；比较区只说明两次采集之间的差异 |
| 从现有日期入口查历史 | `/battle/?mode=ladder&date=2026-02-13` 等继续可用；未登记日期保留未知并链接档案 |
| 从通用规则继续研究 | 参赛规则页链接历史禁赛与费用/兑换变动 |
| 从站内搜索发现 | 搜索“天梯历史”“历届”“历史禁赛”等定位档案入口 |

早期写死的 2025-11-28 跳转被统一数据查询替代；原始公告已经读到，原有同日与 12 月 2 日的系别资料保留。旧巅峰日期链接保留结算预告与结算事件。当前无历史日期的天梯/巅峰查询继续使用现有官方配置；历史记录不改变宠物当前费用、禁赛筛选或排序。指定档案链接带记录 ID，优先展示对应观测或原公告，不被周更摘要覆盖。

历史页面使用已有柔和视觉、原生链接与选择框，筛选和所选记录写入 URL。数值届次和编号采用精确匹配，例如查 42 届不会因为宠物编号 2421 而误命中第 12 届。缺记录时不会静默展示另一条最新记录。

## 继续积累配置历史

天梯更新任务现在同时维护当前快照与历史文件。解析和数据校验完成后，先保留前一份与新一份观测，再原子写入当前快照；中途失败后重试不会重复追加已有记录。

连续相同的源内容不产生重复历史，也不刷新既有观测的采集时间。A→B→A 会保留三次变更观测。同一原包指纹能证明以前未提取的奖励字段属于旧包时，可以补齐该字段；已有奖励解析发生冲突时不静默覆盖。

完整读取、合并与写入过程使用跨进程互斥，进程退出会自动释放。奖励格式不支持或提取冲突会记录状态并保留已有奖励，不阻断有效费用和禁赛的刷新。强制刷新后的时间戳差异、先归档后写入当前文件失败，也能按等效原包内容协调后重试。

这条自动更新路径保存的是配置变化。公告中的完整赛季时间、互斥、商城和奖励条件仍需从原文整理，不由 XML 的采集时刻推算。

## 后续补录顺序

1. 补齐尚缺届次、历史服装/边框及领取形式；优先保留原公告或可追溯游戏界面证据。
2. 补赛季起止、领奖期限、停办与复开；分别建字段与来源，不用结算预告活动范围代填。
3. 追溯旧互斥、禁赛位数、巅峰门槛与魔力体系调整；将现行规则与已失效规则明确分开。
4. 扩大禁赛年份覆盖；频率与趋势统计以实际覆盖期为分母，不把缺失期计成未被禁用。
5. 收集有明确版本的每日任务、成就、段位宝箱和商城交换条件；来源不足时继续保留缺口。
