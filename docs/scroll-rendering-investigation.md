# Linux Chrome 滚动黑块与错位调查

日期：2026-10-11。对象：用户桌面 Chrome 打开的 localhost 站点，个人中心及首页等多个页面。

## 结论

已确认异常依赖 Chrome 的图形加速路径。用户保持同一 localhost 页面，关闭 Chrome「设置 → 系统 → 使用图形加速功能（若可用）」并重启后，确认黑块与错位均消失。

这项对照测试定位到浏览器 GPU 绘制路径，但不能单独区分 Chrome 合成/栅格化、NVIDIA 驱动与 Wayland 桌面合成器的具体缺陷。不能据此宣布某个 CSS 属性或某个驱动版本为唯一根因。

## 现场证据

- 用户截图包含大块纯黑区域、局部卡片重复、旧画面残留；异常覆盖多个页面。
- 桌面 Chrome 的 GPU 进程使用 `--ozone-platform=wayland`；机器为 NVIDIA GeForce RTX 3060，驱动 `615.71.09`。
- `nvidia-smi` 调查时快照：总显存 `6144 MiB`，已使用 `5422 MiB`；`gnome-shell` 占用 `4199 MiB`。这是显存压力线索，不能仅凭一次快照判定内存泄漏。
- 当次启动的内核日志在 `06:35:14` 连续四次记录：`Failed to allocate NVKMS memory for GEM object`。它证明驱动发生过显存对象分配失败；未同步采集出错帧，不能断言每个黑块都对应这四条日志。
- 无界面 Chrome 对 `http://localhost:3000/` 的 DOM 与滚动位置检查未见异常；滚动后截图未出现黑块。该浏览器使用 `--ozone-platform=headless --use-angle=swiftshader-webgl`，不能替代桌面 Wayland/NVIDIA 回归。
- 最有力的对照证据是用户确认：桌面 Chrome 关闭图形加速并重启后，同一站点滚动正常。

## 当前处理

保留用户已验证有效的关闭图形加速配置。此次没有改动页面布局，也没有通过强制 `translateZ(0)`、全局滚动重绘或禁用全站动画来掩盖异常；这些操作尚无对应的定位证据。

若后续需要恢复图形加速，再用独立 Chrome 测试配置比较 Wayland 与 X11、检查当时的 `chrome://gpu` 和驱动日志，并记录显存占用。修改系统驱动或桌面配置应作为独立维护任务，不在本次网站代码调查中自动执行。

## 复核方式

1. 在 localhost 首页、个人中心和图鉴反复上下滚动，确认没有黑块、重复画面或残留。
2. 保持页面及站点代码一致，分别记录图形加速开/关两种状态；切换后重启 Chrome。
3. 若关闭加速后仍再次异常，采集新的页面地址、截图与 `chrome://gpu`，重新检查 DOM 与绘制；本次结论不覆盖这种新情况。

调查命令为只读：`nvidia-smi`、针对 Chrome 进程的 `ps`、`journalctl -k -b`。未终止用户浏览器或桌面进程。
