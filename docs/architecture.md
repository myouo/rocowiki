# 当前架构与边界

2026-10-11 更新。本文记录架构重构、权限和响应式复核；外部身份服务、GitHub App 与生产数据库尚未完成配置和实际联调。

## 模块分工

- `apps/web/src/wiki/community/`：个人中心、共建页面、工作区模型与浏览器存储适配器。模拟审核、历史版本、旧编辑器及示例数据集中在 `community/demo/`。
- `catalog/`：宠物目录/详情/获取/对位、技能目录/详情、血脉、搜索、公共组件及派生模型。
- `world/`：冒险、地区、NPC、赛事、挑战、道具和任务；旧活动/赛事实现集中在 `world/legacy/`，当前路由继续使用新版活动组件。
- `tools/`：对比、能力计算、伤害计算、表单状态与公共字段组件。原 `CommunityPages.jsx`、`CatalogPages.jsx`、`WorldPages.jsx`、`ToolsPages.jsx` 保留为入口，分别为 58、13、67、69 行。
- `wiki/content/bundled.js`：开发者维护的静态资料及生成快照的唯一前端导入位置。阅读组件与编辑基线共同依赖这些输入；迁移真实资料时替换此适配层的输入，不逐页改写 import。
- `features/workbench/`：正式接口契约、HTTP 服务与页面状态控制器。页面负责呈现，端点、响应校验、草稿解码和请求取消在此集中管理。
- `packages/wiki-schema/src/protocol.ts`：API 与浏览器共享的正式投稿类型和状态码，不依赖数据库或资料目录。

`npm run check:architecture` 纳入根目录 `check`，检查前端文件不超过 1000 行、资料导入边界、模型不依赖 UI，以及新拆分领域目录内的循环依赖。它是结构门禁，不能代替业务和浏览器验证。

## 数据权威与编辑

正式内容仍由根目录 catalog/schema 登记，Git 保存已审核内容，D1 保存身份、私有草稿、投稿、审核、发布任务与审计。正式服务支持文章、宠物、技能三种投稿；尚未登记的条目不会自动进入正式编辑器。目前 catalog 只有两篇文章，后续真实资料登记仍需逐项推进。

根内容生成器同步生成 `src/generated/search.json`，读取相同的已验证公开内容；`getSearchRecords` 合并该输入，正式文章的标题、公开正文和实体别名自动进入现有全站搜索。结果按名称优先排序，正文匹配只展示短摘要；不会索引私有草稿或账号数据。Pagefind 制品索引仍生成，但当前搜索页面采用目录与共建内容的自动合并记录，未声称已调用 Pagefind 浏览器 SDK。

```mermaid
flowchart LR
  Reader[阅读页面] --> Gate[账号与权限验证]
  Gate --> Workbench[正式工作台]
  Workbench --> API[Workers API]
  API --> D1[身份 草稿 审核 任务]
  D1 --> Coordinator[发布协调器]
  Coordinator --> PR[Git 内容 PR]
  PR --> CI[独立合并与构建]
  CI --> Site[静态站与版本清单]
  Site --> Coordinator
```

游客直接访问编辑地址也会先进入登录提示；只读账号无法挂载编辑表单，贡献者不能使用审核员入口。前端通过 `/me` 获取身份，不把 localStorage 的 UUID、昵称或角色作为登录证明；API 原有 Session、Origin、CSRF 和角色校验继续承担最终授权。

浏览器演示保留本机草稿、积分、点赞及样本预览。正式阅读模式忽略浏览器中的“本机发布”覆盖，不展示本机投票/讨论冒充公共记录，也不自动将旧积分导入 D1。

## 运行模式

- `WIKI_WORKSPACE_MODE=server`：正式账号、审核及已登记编辑入口进入服务端工作台，未登记对象显示说明。
- `WIKI_WORKSPACE_MODE=demo`：保留导入界面的演示能力；编辑和审核仍须通过账号与角色验证。
- 开发环境默认 demo，正式构建默认 server；独立 HTML 明确是离线演示。离线页面没有可用身份服务时只能阅读，不能把本机身份当作登录。
- 正式构建必须显式配置合法 HTTPS Origin 形式的 `API_ORIGIN` 与 `SITE_URL`；缺少配置直接失败。开发模式及离线演示仍可在服务未配置时显示未开放状态。
- 正式构建使用 `.docusaurus-build`，开发服务器使用 `.docusaurus`，避免构建覆盖正在运行的开发站元数据。

## 服务端缺陷修复与回归

- 审核队列返回完整的投稿状态字段。联测使用真实 Hono 路由与 SQLite 数据库，经前端 `createWorkspaceService` 解析空队列、普通投稿、关键页投稿、详情及审核响应，防止接口与 UI 契约各自通过却互不兼容。
- `/me` 不再轮换 CSRF。新令牌由 HttpOnly 会话的随机 secret 经带用途前缀的 SHA-256 派生，同一会话内稳定，数据库继续只保存摘要。旧会话的既有随机 CSRF 仍可使用至过期或撤销；重复和并发账号查询不修改会话记录。新会话不会接受前一会话的令牌，Origin、角色及会话有效性仍在每次写入时检查。
- 私有草稿的请求上限为 1 MiB，覆盖两份各 64 KiB 正文、JSON 最坏六字节转义与元数据；其他端点保留原有上限。声明长度和实际读取字节均受限，超限取消读取并返回 413，不写入或覆盖已保存草稿。草稿配额仍为每用户 20 份。该上限低于 [D1 单字符串/行 2 MB 限制](https://developers.cloudflare.com/d1/platform/limits/)，正文通过绑定参数写入，不拼入 SQL。
- Markdown 复用 remark 的标识符归一化，再使用渲染器同样的大小写查找规则；重复引用定义一律拒绝，包括两个目标都安全的重复定义。图片引用与渲染共用同一 AST；预览 API 对此返回 400。覆盖完整、折叠、简写引用及大小写、空白和 Unicode 大小写等价场景。
- `GitCandidate.coauthor` 始终传入不可变的投稿署名快照；已有分支的提交消息可匹配该快照或合法省略署名的版本，并核验正文、父提交的基线 blob、来源元数据。新提交通过独立回调读取当前授权，在写入 commit 和发布 ref 前复核；撤销/解绑后不再向新提交添加署名。恢复已创建的分支/PR 不重写历史署名，仍须租约有效才可创建新的 PR。

发布恢复联测使用真实 Coordinator 和 GitHub HTTP 适配器：远端已创建 ref 或 PR 但响应丢失，D1 尚无 Git 关联，随后撤销署名，再启动新协调器，复用原提交和唯一 PR。另覆盖新写入前撤销、写入过程中撤销、丢失租约，以及正文、署名、基线、来源被篡改时拒绝恢复。未调用真实 GitHub 写入 API，也没有部署外部服务。

## 发布恢复与前端验证补充

- 正式构建与部署都引用 GitHub production environment。根构建在开始前检查公开地址，Docusaurus 配置本身再检查，防止绕过根脚本。PR 构建使用显式测试地址；本地已验证生成的客户端 bundle 含配置的 API/站点地址，workbench 的 canonical 地址也匹配。
- 发布任务在持久化 Git 关联后中断，可将原始 GitLink 传回适配器恢复；核验原始单父内容提交，再检查更新后的分支头是其后代、正文及元数据一致。返回值始终保留原始内容 SHA；正文、来源或祖先关系改变时转冲突。
- `0003_publication_reconciliation.sql` 保存回滚巡检游标、固定终点、批次的可信 release、租约及完成轮数。默认每批 10 条；写入事件与推进游标原子化。版本变化保留游标，每批检查当时的可信版本，避免频繁部署使后续记录饥饿。覆盖 101 条全量扫描、同时间戳、数据库关闭重开、新记录加入、每批版本都变化、并发、旧租约、读取失败和事务失败，不再只巡检最新 100 条。
- 正式 Workbench 已加入根测试门禁：挂载实际页面与 controller，经真实 API/会话/SQLite 完成草稿、投稿、审核、登出及权限验证；只有外部 OIDC 跳转是替身。覆盖保存/投稿已成功但响应丢失，再显式重试；草稿 PUT ID 与投稿幂等键均保持稳定。另在隔离 Chrome 中检查原生 DOM 的相应操作，身份与 API 使用显式 fixture，记录见 `apps/web/validation/workbench-browser-results.json`，不能当作真实服务验收。
- `typecheck:web-critical` 开启 JS 解析，并对 RequireRole、BoundedTextarea、profileModel、workspaceRepository 使用 `@ts-check` 与 JSDoc；未知存储数据需要校验，角色和组件参数受类型约束。反向类型断言防止接口退化为 any。该阶段采用逐文件启用，仍未对所有旧 JS/JSX 开启全局 checkJs。

后续排期：先补 EntityTextarea/FloatingPanel 与编辑模型的类型，再覆盖各资料领域的派生模型及页面；将当前可复用 Chrome fixture/journey 纳入独立浏览器 CI runner。外部 OIDC/GitHub/D1/Workers 静态托管 的真实端到端验收继续按运维手册执行，组件测试与浏览器替身不会将其标记为完成。

## 本轮认证与巡检修复

- OIDC code grant 显式校验最大认证年龄，要求 `auth_time`，会话记录提供商认证时间。旧会话通过 0004 迁移失去近期认证标记，登录及草稿保留。测试调用真实 openid-client grant 实现，只有提供商 HTTP/发现端点使用替身；覆盖旧 SSO、去除 URL 参数、缺失/异常时间、时间窗口不延长及正常同 UID 换发会话。
- 固定提交的 Contents 404 经 Git 树确认后才作为已删除文章；权限、限流、网络和未确认 404 持久化到 0005 新增的单条错误表。游标、事件和错误原子提交，少量到期重试与正常巡检共享额度。正常记录不被一篇异常文章阻塞，失败记录也不会因游标前进而永久失去检查机会。
- 两篇正式文章在实际 SearchPage 组件和 Chrome 中均可按完整标题检索并指向正确的 `/wiki/` 路径；新增公开资料会自动生成搜索记录，正文摘要保持有界。
- mirror 配置检查在 production 环境已启用后的步骤执行，观察步骤只引用该步骤的输出；job 级条件不再依赖尚未可用的环境变量。
