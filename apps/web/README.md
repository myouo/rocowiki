## 社区指标与币制

洛克印记用于纪念物展示。每天签到随机获得 3、4、5、6 或 7 枚，各 20%；连续第 7、14、21……天额外获得 5 枚。预览使用 Web Crypto 无偏取样并把实际奖励写入账本，重复签到不会重新抽取。重复兑换、余额不足和存储失败不会改变资产；漏签不清除累计和历史最长纪录。本版不提供补签。

首页名片显示最近七天；完整签到页默认自然月，可切换周一开始的自然周、翻阅历史并返回当前周期。周/月只是查看记录的方式，连签跨周、跨月持续累计，不在月初清零。

印记可兑换「初见王国 5」「云间旅人 25」「星光书签 50」徽章，以及「暖阳 10」「星夜 30」头像框。第一笔修订、资料拾光者和七日之约由实际记录解锁。成长徽章继续使用符合主题的 SVG；头像框的光晕与星点由 CSS 实现，动态主要改变透明度与变换，降低重复绘制成本，减少动态模式保留静态高光。货币不能购买点赞、专业资格、可信度、审核权限或榜单权重。

注册 UID 表达「服务器的第几位注册用户」，由服务器原子分配且不可修改。UUID 保持稳定身份、投稿与互动关联。预览不会使用浏览器时间、随机数或 UUID 片段伪造注册排名；个人资料内的「注册后的展示样式」带明确示例标签。

社区足迹的四类指标分别进入对应记录。评论有可直达的原评论锚点，贡献有原小节与审核记录，空状态提供相关参与入口；时间范围写入查询参数。取消点赞、移除评论和无效投稿不会继续显示为有效影响力。

排行榜按北京时间分期，周一开始，同分同名次。连签榜使用周期内达到的最高连续签到纪录；贡献按不同投稿 ID 首次发布去重。只统计有实际修改的已发布贡献，示例、无作者 UUID 和待审稿不计入。取消点赞会撤回统计，重新点赞保留第一次点赞日期；不能给自己点赞。Counter 票独立于攻略和评论获赞。

每页维护人员使用累计有效改动行：过滤空白和仅有排版符号的行，取每次修订新增和删除的较大值，按投稿 ID 去重。这不是当前文字逐行所有权，也不发放印记。旧稿缺少 UUID 时不通过昵称猜测作者。

正式部署应使用服务端身份和时钟、唯一签到键、事务账本、点赞幂等、软删除、审核与申诉。浏览器本机数据不具备公共排行榜的可信性。

后续优先级：关注条目与更新通知 → 专题协作小任务 → 可复现的战斗实验记录 → 经审核的专业贡献徽章 → 年度参与回顾。完整设计见 `content/community-ecology-v73.json`。

装备分为饰品、武器、防具三个槽位，分别修正精力、攻击侧主属性、防御侧主属性。已收录五件 100 级史诗装备；未收录装备允许按游戏面板填写主加成，并标为手动资料。命中、闪避、暴击与抗暴附加项是四选一，不并入六维能力。手动输入范围是工具校验边界，不声称是游戏装备上限。

简易面板把等级、性格、守护兽放在第一行，直接展示结果，天赋/努力以六列分配；装备与亲密在可展开区域。保存记录会同时写入宠物身份、性格、等级、六维培养、装备、守护兽等级、结果、时间与映射版本。最多保留 40 条，由用户选择删除；存储不可用、内容损坏和写入失败时显示原因，不假报成功。

可在当前宠物或全部记录中任选 A、B 两条。对比显示 B−A、面板与战斗基础能力、性格和培养参数差异；跨宠物明确说明含种族差异。载入旧参数按当前版本重算，原保存结果保持不变。切换宠物会清空当前选择与临时参数，其他宠物的旧记录通过完整工具载入，避免串用图鉴数据。

资料依据是官方论坛原文，不是当前客户端源码或逐级账号实测。威力伤害原有公式与权威算例继续回归验证，特殊技能仍以单独条目规则为准。

## 内容模型与编辑

活动保持主条目与多个 `occurrences[]`，每次返场独立维护日期、条件、地点、奖励与来源。宠物和技能用稳定身份，改名不丢已有关系。PVP Counter 只记录对战关系，PVE 从玩法页单向查队伍和出招步骤。

技能流程区分独立条件与互斥否则关系；没有证据时不从排版推断结算先后。回合条件支持离散或连续区间、不同计数依据和嵌套 AND/OR。纵/横切换保留阅读偏好，窄容器自动转成纵向并说明原因，加宽后恢复横向。Mermaid 导出方向与当前实际视图一致，使用生成的节点 ID 和转义标签，不执行用户 Mermaid/HTML；未运行完整 Mermaid 布局器。阅读界面本身无 Mermaid 运行时依赖。

学习宠物聚合原始归属、宠物技能池与后续学习关系，以宠物稳定 ID 去重，不为凑数量创造关系。紧凑卡片提供宠物图像、名称、学习方式和来源；支持搜索与分批展开。专用编辑器允许一次选择多只宠物，补充学习等级、方式与来源。删除补充记录不会删除原始技能池中已有的关系。

斜线插入标准内部 Markdown 链接。实体渲染在读页、编辑预览和原生 MDX 链接主题中共用；未识别链接沿用正常链接。预览点击只展示去向，保留草稿。新旧编辑器底部返回会先确认草稿持久化，失败则留页。

所有长文本入口改用 `BoundedTextarea`，底层保留原生文本输入与中文输入法行为，尺寸控制由统一组件接管。宽度受父容器限制，高度可自动适配、拖动或键盘调节；不再放任系统双向缩放柄突破卡片。下拉弹层、斜线候选、测量和指针监听使用控件所在的 `ownerDocument` 与 `defaultView`，嵌套 iframe 中不借用母页面视口。

阅读预览对文档准备、尺寸订阅、动画帧和卸载分别管理；清理过期观察器与事件监听，限制尺寸回写循环。阅读内容、预览外框和页面层各有可恢复错误边界，局部异常时保留其他页面操作。自动检查覆盖实际 iframe 文档归属及人工注入的故障；屏幕比例和浏览器缩放的真实视觉验收仍见下文边界。

`pve-guide` 是第 11 种专用模式，创建的是玩法条目；`pve` 仍维护一份挑战方案。新增玩法、分区均分配稳定 ID；发布后目录、详情与下一次编辑读取同一份记录。资料来源与核对日期必填，未知 Boss 和奖励留空。

七曜的基础数量保留历史资料标签，现行 Boss 名单与完整数量仍待客户端复核。官方 2025 LITE 说明的截图明确是测试数据，不能拿它补造当前对手。山海召唤为使用印记和魂珠的随机奖励活动，放在奖励区。

本次环境使用 Node.js 24.19.0、Docusaurus 3.10.2、React 19.3.0。锁文件保留精确依赖；Node 支持范围见 `package.json`。

```bash
npm ci
npm run check:content
npm run build:preview
npm run build
npm run check:v731
npm run build:report
```

`build:preview` 和 `build` 会先生成知识文档及已收录小节的编辑基线；两种构建顺序执行，避免并发覆盖。`check:v731` 运行横向流程、共用目录/新增组件和最终产物三组定向检查。交付报告从当前结果中汇总通过数，核对源码和最终 HTML 的 SHA-256；过期结果或失败不生成「已验证」的报告。旧版测试保留作历史记录，不叠加其数量。

最终集成检查读取实际 `build/` HTML、链接和锚点，核对各页结构与编辑入口、编译 CSS 的资源依赖、原图与字体的字节摘要，再执行精确交付的单文件 HTML。个人足迹→原评论、计算记录对比、签到视图、编辑预览→保存草稿等均为实际 DOM 交互。仅有控件名称或源码关键字，不等同于功能通过。

需要开发服务时：

```bash
npm run start
npm run serve
```

### 字体与图像

英文页首与页脚字标使用 Georgia。中文为基于 Noto Sans SC 的本地 Roco Wiki Sans 子集，保留 OFL 授权、源 SHA 与覆盖报告。新文本加入后可使用 `scripts/build-fonts-v7.py` 重建；需要 fonttools 和 brotli。传入本地许可证时使用独立副本，不传输出许可证本身。

首页原始官网背景来源 [游戏官网背景](https://res.17roco.qq.com/images/bg.png)，出处和字节摘要见 `content/decor-assets-v71.json`。九个一级入口分别使用宠物园、图书馆、魔法课教室、皇家研究院、魔法嘉年华、绿野擂台、王者之地、天空城和宠物训练室，来自 [官方论坛页游场景资料](https://17roco.gamebbs.qq.com/forum.php?mod=viewthread&tid=164058)。具体楼层、原图 URL、尺寸、SHA-256 和页面对应关系见 `content/scene-assets-v73.json`。

场景文件保留下载的原始字节，未使用 AI 生成或修改图片。渐变只作用于承载图片的背景层：首页使用 `WelcomeBackdrop`，其余页首使用独立伪元素。图片左侧透明，向右逐渐清晰，底层卡片与正文保持白底和完整透明度。海芙约忒外观图的来源和 SHA 见 `content/pet-appearances-v72.json`。原生版本按使用场景请求图片，独立预览为便于直接打开而内嵌，因此单文件体积较大。

### 保留的生产架构

| 层 | 职责 |
| --- | --- |
| Docusaurus | 阅读、稳定地址、目录、搜索与内容构建 |
| 独立 Wiki 账号 | 服务端注册 UID、稳定 UUID 与投稿身份；GitHub OAuth 可选 |
| Workers / Hono | 认证、投稿、审核、投票、账本和发布 API |
| D1 | 用户、草稿、审核状态、签到与资产、互动记录 |
| GitHub App / GitHub | 每次投稿独立提交，普通合并，保留历史，不 squash |
| GitCode | 单向国内镜像 |
| EdgeOne | 静态内容分发 |

已有能力与威力伤害公式保留，能力计算器增加可维护的等级与装备映射，两种能力界面复用同一核心。历史算例在 `validation/fixtures/`，不代表游戏每一个特殊技能都被验证。

## 验证边界

最终检查数量和逐项结果见 `RocoWiki_Design_V7_3_1.html` 与 `validation/v731-delivery-summary.json`。各组原始 JSON 记录源码摘要；最终集成结果另记录预览 SHA、原生页面 SHA 和编译 CSS SHA，便于判断结果是否对应当前交付。

本次执行本轮改动的 DOM 交互、流程图节点关系、目录组件、资源完整性和原生静态构建检查。已有跨 iframe 生命周期处理保持原样，剩余生命周期问题按用户要求交由项目维护者继续修复。管理型环境没有执行真实浏览器逐屏截图、多设备几何布局、浏览器实际缩放和帧率验收；CSS 契约、模拟尺寸和 JSDOM 不能代替视觉验收，也不能证明任意嵌套宿主环境都不存在黑屏。真实账号、公共互动、远端审核与部署尚未连接。
