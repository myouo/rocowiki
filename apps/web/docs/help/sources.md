一条资料应能回答：依据来自哪里，支持哪句话，何时取得，适用于什么范围。来源和结论一起维护。

## 不同来源分别标记

| 来源类型 | 适合支持的内容 | 需要附带 |
| --- | --- | --- |
| 官方页面或公告 | 活动、说明、公开调整记录 | 原始链接、标题、日期与相关位置 |
| 游戏内资料 | 当时显示的字段与原文 | 截图、记录日期、对象与上下文 |
| 配置或源码记录 | 对应文件中的字段与逻辑 | 文件来源、版本、字段位置与解释范围 |
| 可复现实测 | 指定条件下观察到的行为 | 配置、步骤、样本与完整结果 |
| 社区整理 | 查询线索与已有分析 | 作者、链接，并尽量追溯原始证据 |

源码或配置记录反映的是该份材料；是否对应当前服务端行为，需要额外核验。

## 原文与解析分开

引用原文时保留含义和必要上下文。解析可以分段、标注条件与关联机制，但不把推断写进原文，不把缺失条件补成确定规则。

技能的先手、PP、伤害描述与特殊效果可能来自不同来源，允许字段拥有独立证据，而不只在页脚放一串链接。

## 资料状态

| 状态 | 使用原则 |
| --- | --- |
| 已核实 | 明确证据、验证范围与日期 |
| 待核实 | 已有条目或线索，仍需来源支持 |
| 存在分歧 | 展示差异与各自证据，不强行合并 |
| 历史资料 | 记录曾经适用的内容和时间 |
| 来源失效 | 保留可追溯信息，补充存档或替代证据 |

“没有记录”“明确不存在”“当前无法判断”使用不同空态。

## 最小实测记录

记录目的、日期、场景、参与宠物与完整配置、开始状态、操作过程、实际结果和异常样本。一次结果不能证明概率分布；公式也需要说明推导条件与验证覆盖。

涉及 [PP](/mechanics/pp/)、[行动次序](/mechanics/priority/) 或 [护盾](/mechanics/shield/) 时，按对应文章要求补足状态。

## 提交前检查

确认链接指向具体内容、结论没有超出证据范围、历史资料没有被误写成现行规则。带着字段或段落位置进入编辑，有助于审核者复核同一问题。
