从需要修正的词条进入编辑，系统会保留当前对象。补充来源、纠正字段、完善文字都可以成为一次独立投稿。

## 从具体资料开始

| 想做什么 | 推荐入口 |
| --- | --- |
| 修正宠物或技能字段 | 对应详情页的编辑入口 |
| 补充当前获得方式 | 宠物的获取章节或具体活动页 |
| 补充机制证据 | 对应机制文章的编辑入口 |
| 报告资料或页面问题 | 页面的反馈入口 |
| 查看自己的进度 | [个人中心](/account/) |
| 查看已采纳的修改 | [贡献与修订](/community/) |

社区用于协作、贡献记录、审核与反馈。新内容的整理从相关资料和维护需求出发，不设置孤立的“创建词条”流程。

## 一次修订写什么

写明修改内容、依据和适用范围。结构化字段通过表单修改；正文使用受限 Markdown。提交前比较修改前后内容，确认没有带入无关改动。

来源应尽量直接定位到所支持的字段或句子；方法见 [资料来源规范](./sources.md)。

## 审核通过后还有发布过程

| 状态 | 含义 |
| --- | --- |
| 草稿 | 尚未提交，作者可继续编辑 |
| 待审核 | 已形成投稿，等待核对内容与来源 |
| 需修改 | 审核意见要求补充或调整 |
| 已通过 | 内容通过审核，等待后续合并与构建 |
| 发布中 | 正在合并、构建或分发 |
| 已发布 | 对应修订已在站点可见 |
| 发布失败 | 内容保留，维护者可查看失败原因并重试 |

页面按实际进度显示状态。已通过审核的内容仍可能等待发布；查看“已发布”状态后，可回到对应词条核对线上内容。

## 遇到版本冲突

保留自己的草稿，对照“开始编辑时的版本”“当前线上版本”“自己的修改”。确认冲突部分后重新预览，再提交新的修订。

他人的更新不能因一次过期投稿被静默覆盖。投稿记录应保持作者、来源、差异和每次修订的可追溯性。

## 当前原型的范围

界面用于演示编辑、差异、审核与发布状态。正式账号、云端草稿和实际发布尚未开放；本地预览的状态变化不代表线上投稿成功。
