先查“这一段伤害从哪里来”，再查它受到哪些效果影响。一个技能可以包含多项伤害与治疗，最终精力变化不能代替每项结算记录。

## 伤害按来源查

| 查询类别       | 阅读重点                                   |
| -------------- | ------------------------------------------ |
| 威力伤害       | 技能威力、物理或魔法类别、属性及临时修正   |
| 固定或比例描述 | 数值基准、上下限和取整位置                 |
| 附加伤害       | 触发条件、来源技能或血脉、发生时点         |
| 反伤与反弹     | 反回的对象、内容与时机，是否改变技能作用者 |
| 波及           | 场下目标选择、伤害范围及能否致死的具体条目 |
| 自损与代价     | 何时支付、触发失败时是否仍支付             |

这些是资料的查询类别，并非对所有技能适用的伤害公式。

## 同一技能逐段阅读

每段分别展示对象、类型、基准和命中要求。造成伤害前后的回复、状态清除、标记施加与 PP 变化，在 [技能阶段](./stages.md) 中保留原有顺序。

“最大精力”“当前精力”“已损精力”直接显示在数值旁边；伤害上限和最低值也与对应伤害项放在一起。

## 多种保护效果同时存在

从 [护盾与减伤](./shield.md) 查每种保护作用于什么，再进入 [覆盖与共存](./interactions.md) 查它与其他效果的关系。比较的对象可能是两个持续效果，也可能是伤害转换与保护效果之间的结算顺序。

在没有完整证据时，不把护盾、限伤、转化、反伤排列成一条通用顺序。

## 计算工具的适用边界

[伤害计算器](/tools/damage/) 使用官方论坛版主团的[《威力伤害计算器》](https://17roco.gamebbs.qq.com/forum.php?mod=viewthread&tid=162103)公开模型，原帖工具编辑于 2026-10-06，本站于 2026-10-23 重新核对。它支持普通物理、魔法威力伤害，以及分别输入攻防强化、五档属性关系、已知总增伤和总减伤。

物理配对物攻与物防，魔法配对魔攻与魔抗。输入能力**尚未计入工具下方的强化等级**；如果填入的数值已计算强化，对应强化应设为 0，避免重复计算。

固定伤害、斩杀、护盾、限伤、锁血、伤害转化、多段与波及仍需对应规则，不能用一个减伤百分比代替。工具不会自动读取全部血脉、天气或本系等特殊修正，也不判断多个效果能否叠加；输入总比例前须先核对来源和覆盖关系。

## 现行威力参考模型

设强化等级为 `s`，正强化倍率为 `(s + 2) / 2`，负强化倍率为 `2 / (2 - s)`，0 级倍率为 1，范围 −6 至 +6。命中、回避等级不套用这个攻防倍率。

```text
A′ = 输入攻击 × 攻击强化倍率
D′ = 输入防御 × 防御强化倍率
B = (0.4 × 攻击方等级 + 2) × 威力 × A′ / D′ / 50 + 2
参考伤害 = max(1, floor(B × 属性关系 × r × (1 + 增伤/100) × (1 - 减伤/100)))
```

`floor` 表示向下取整。本站保留中间分式，仅在最终伤害取整；最低值 1 也属于这个**公开工具的模型约定**。它们不是本站已经证明的服务端取整顺序，100% 减伤等边界尤其不能直接当作游戏结论。

| 属性关系 | 模型系数 |
| --- | --- |
| 双重克制 | 3 |
| 克制 | 2 |
| 不克制不抵抗 | 1 |
| 抵抗 | 1/2 |
| 强力抵抗 | 1/3 |

这是对本次已知属性判定的选择，不是自动生成的全属性矩阵。双属性和神系的规则另见[属性与克制](./attributes.md)，不能将两次单属性倍率直接相乘。

## 可以手算复核的例子

设等级 100、威力 100、攻击和防御都为 300、无强化、普通属性关系、增减伤均为 0：`B = 86`，模型输出 68–86。

只把攻击强化改成 +2，则 `A′ = 600`、`B = 170`，区间为 136–170。只把防御强化改成 +2，则 `D′ = 600`、`B = 44`，区间为 35–44。这些是合成输入的计算演示，不是实战测试；也说明攻防倍率不能简单移到整个伤害式最外层。

若已另行确认总增伤 50%、总减伤 20%，原始输入的整体修正为 `1.5 × 0.8 = 1.2`，输出 82–103。该例只展示已确认总比例的运算，不证明任意两种增减伤效果都能这样组合。

## 随机浮动与证据状态

本轮直接核对的论坛公开工具枚举以下 21 档：

```text
r = 0.80、0.81、0.82、……、0.99、1.00
```

这些档位固定枚举，不允许任意输入浮动上下限。不同系数取整后可能产生相同整数；枚举本身不证明各档等概率，因此不据此提供精确击杀概率或实战必杀承诺。

历史线索保留超级楚的無頭于 2022-06-14 发布的[原始实测视频《揭开伤害浮动机制的真面目》](https://www.bilibili.com/video/BV1dY4y1W7om/)：约 04:00 的频数表及约 04:30 的逐档对照。它没有在本轮升级为当前版本实测；片头取整括号存在歧义，不作为客户端中间取整的依据。当前行为仍需按[实测规范](./evidence.md)留存完整样本。

## 从培养得到实际能力

[能力计算器](/tools/stats/) 使用官方论坛版主团[《PK入门·1》宠物能力培养指南](https://17roco.gamebbs.qq.com/forum.php?mod=viewthread&tid=162202)末楼的六维公式图（公式段编辑于 2026-04-14），并将面板与守护兽的战斗加成分开展示。

```text
E = floor(努力值 / 4)
B = floor((2 × 种族值 + 天赋 + E + 亲密值) × 等级 / 100)
精力 = B + 等级 + 10 + 装备 + 守护兽
非精力 = floor((B + 5) × 性格修正) + 装备 + 守护兽
```

这里的亲密值包括已分配点数和关系的额外加成；速度的亲密、装备与守护兽项均为 0。性格使用精确的 `9/10、1、11/10` 比值计算，避免十进制乘法误差改变向下取整结果。能力计算所得是尚未叠加战斗中强化、血脉和临时效果的基础值；带入伤害工具后，要按当次出手条件继续核对。
