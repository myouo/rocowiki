判断行动次序时，把**技能先手值、宠物速度、特殊行动条件**分开核对。技能说明中的条件不能省略成“速度更快就一定先动”。

## 两个数值放在哪里看

| 字段 | 所属资料 | 需要保留的上下文 |
| --- | --- | --- |
| 先手值 | 技能 | 使用的具体技能、条件触发前后是否变化 |
| 速度 | 宠物与本回合状态 | 实际能力、强化或弱化、相关持续效果 |
| 特殊行动条件 | 技能、血脉或战场效果 | 谁触发、作用于谁、持续到何时 |

[查询技能先手](/skills/) · [查询宠物资料](/pets/) · [查看血脉](/bloodlines/)

## 一次比较的核对顺序

1. 写明双方本回合选用的技能。
2. 核对技能先手字段，以及是否满足改变行动次序的条件。
3. 记录双方的实际速度和正在生效的相关状态。
4. 查看是否存在强制行动、换宠、封锁等特殊处理。
5. 对照对应版本的规则与实测记录；资料缺失时保留“尚不能判定”。

以上是查证步骤，不能代替尚未核验的完整服务端排序算法。

技能谁先出手与两个效果谁覆盖谁是不同问题。后者进入 [效果关系对照](/mechanics/relations/)；一次行动里的处理先后进入 [结算时点](./timing.md)。

## 实测记录至少包含什么

| 必填记录 | 用途 |
| --- | --- |
| 双方宠物、技能与血脉 | 重现参与者与能力来源 |
| 速度面板、强化状态 | 排除培养差异 |
| 回合开始时的天气、环境与标记 | 确认外部条件 |
| 本回合操作与实际先后次序 | 对比预测与结果 |
| 测试日期、规则场景、截图或录像 | 判断证据是否仍适用 |
