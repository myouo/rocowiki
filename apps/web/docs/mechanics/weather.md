天气与环境在资料中分别归类。页面先展示作用与来源，再记录持续、清除、覆盖或锁定的条件；不从名称推测结算关系。

## 一条战场效果的资料

| 字段 | 玩家需要知道什么 |
| --- | --- |
| 名称与类别 | 查到的是天气还是环境 |
| 效果原文 | 影响对象、能力、技能或其他状态 |
| 产生来源 | 哪些技能、血脉或规则会产生它 |
| 持续条件 | 持续时长的依据，以及延续或结束条件 |
| 覆盖与清除 | 谁能替换、清除，是否存在条件 |
| 适用版本 | 来源日期与已验证范围 |

## 锁定不应只显示一个图标

锁定的对象、来源与解除条件应与战场效果一起记录。只标“已锁定”不足以解释一次覆盖失败，也无法让其他玩家复现实测。

查询具体技能时，保留原文中的前置条件及作用范围；暂未验证的相互关系显示待核项。

## 召唤、屏蔽和回合变化

召唤成功、未能召唤、现有效果被清除、仍存在但暂不参与作用，以及剩余回合变化，使用不同结果描述。涉及锁定或特殊召唤方式时，按“已有效果 → 新操作”的方向进入 [效果关系对照](/mechanics/relations/)。

时长在什么时候增减、作用何时恢复，查 [触发顺序与结算时点](./timing.md)。未有对应证据时不从图标是否出现推断内部状态。

## 关联查询应保留条件

从某种天气或环境进入技能资料，应获得与该效果相关的技能集合；进入宠物页，应指向真正拥有这些能力的宠物。

[查询相关技能](/skills/) · [查询血脉](/bloodlines/) · [宠物图鉴](/pets/)

## 建议的实测记录

记录效果产生前的战场、召唤技能、当回合阶段、第二种效果的产生方式与最终战场结果。验证“清除”“覆盖”“延长”“锁定”时分别建记录，避免一次测试承担多个结论。
