机制页先展示可用结论，再展示适用条件和证据。原文、玩家解析和实测记录分别标注，读者可以判断一条资料目前能回答什么问题。

## 证据状态

| 状态 | 页面含义 |
| --- | --- |
| 原文记载 | 技能、公告或已说明来源中有直接描述 |
| 历史实测 | 有测试记录，但未完成当前版本复核 |
| 当前已复核 | 有本次测试日期、条件和可定位证据 |
| 存在争议 | 不同记录在相同或待确认条件下发生冲突 |
| 尚未验证 | 目前只有疑问、推测或不完整观察 |

网页“最后抓取时间”与“游戏测试日期”分开记录。只有来源刷新，不会自动升级验证状态。

## 一条配对实测的最小记录

| 记录项 | 示例要求 |
| --- | --- |
| 参与者 | 双方宠物、技能、血脉及与结论有关的队伍位置 |
| 起始状态 | 已有效果、PP、相关能力与天气环境 |
| 操作顺序 | 哪一回合由谁施加 A，哪一回合施加 B |
| 观察时点 | 施加后、触发时、旧效果结束时、换宠后 |
| 结果 | 数值或状态具体变化，以及没有变化的项目 |
| 来源定位 | 日期、规则场景、录像时间或日志回合位置 |

重复实验不只重复同一操作，也应补充逆序、没有另一个效果时的对照，以及已知会改变结果的边界条件。

## 观察和解释分别写

“第 4 回合额外消耗停止”是观察；“B 覆盖 A”是解释。解释需要同时排除到期、免疫、技能未满足条件等原因；证据不足时先保存观察。

没有观察到某效果，不自动认定其内部状态已经删除。现有状态、触发行为和最终数值分别记录。

## 有冲突时怎样处理

并列保留不同结论、各自证据和适用日期。先检查技能调整、操作顺序、作用对象及计数时点差异。仍无法解释时维持争议状态，不按投稿顺序覆盖旧记录。

页内反馈会带上当前页面；在 [效果关系对照](/mechanics/relations/) 中反馈还应保留选中的两个效果与方向。
