## Entry points

Use the support issue template for setup, interface and usage questions; use the bug template for reproducible defects and the relevant templates for content corrections or features. Report vulnerabilities privately under [security](SECURITY.en.md) and conduct issues under the [code of conduct](CODE_OF_CONDUCT.en.md). No public support email, instant chat or ticketing service is configured.

<a id="details"></a>
## Useful information

Include version/commit, operating system, browser, entry point (localhost, production or offline HTML), steps, expectations, actual behavior and attempted remedies. Redacted error codes, screenshots and minimal examples are useful. Remove OAuth code/state, cookies, tokens and private information from URLs. Do not upload unredacted HAR files, database exports or real users' draft content.

<a id="expectations"></a>
## Current limits

This is an initial development project without guaranteed response times or production availability. UI presence does not establish that identity, GitHub App, production D1 or other services are configured. Points, check-ins and likes may still be local demos; consult the architecture document for status. Support never requires a password or a publicly posted commit email.
